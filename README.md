# 实验室共享设备预约与冲突调度系统

## 1. 项目简介

本项目是计算机科学与工程实践课程设计，采用 **C++ + Qt** 开发，面向高校实验室共享设备的预约与管理场景。

系统主要解决实验室共享设备在使用过程中产生的设备查询、预约管理、时间冲突、设备借用与归还、等待任务以及历史记录管理等问题。

项目重点不是简单的信息增删改查，而是研究不同类型数据在内存中的组织方式，并利用数据结构与算法完成高效的数据管理和业务操作。

------

## 2. 项目目标

系统需要实现一个具有完整 GUI 的本地实验室共享设备管理程序，主要目标包括：

- 快速查询和管理用户、设备信息；
- 支持设备预约与取消；
- 自动检测预约时间冲突；
- 管理设备借用、归还及设备状态；
- 维护设备不可用时的等待任务；
- 查询设备借用历史；
- 支持必要的操作撤销；
- 实现本地数据保存与加载；
- 对非法输入和异常操作进行检查；
- 通过 Qt GUI 直观展示设备及预约状态。

------

## 3. 核心功能

### 用户管理

- 用户信息添加、修改、删除；
- 用户信息查询；
- 用户编号唯一性检查。

### 设备管理

- 设备添加、修改、删除；
- 设备分类；
- 设备状态管理；
- 按编号、名称、类型等条件查询。

### 预约管理

- 创建预约；
- 取消预约；
- 查询预约；
- 预约时间冲突检测；
- 预约状态维护。

系统将预约时间统一表示为半开区间：

```text
[start, end)
```

两个预约区间存在冲突的条件为：

```text
start1 < end2 && start2 < end1
```

### 借用与归还

- 设备借用；
- 设备归还；
- 设备状态更新；
- 借用历史记录。

### 等待与调度

当设备暂时无法使用时：

- 普通等待任务进入等待队列；
- 按预先定义的客观规则处理需要优先调度的任务；
- 设备释放后更新相关任务状态。

### 操作撤销

保存管理员的重要操作记录，并支持撤销最近一次可撤销操作。

### 数据持久化

- 程序退出前保存数据；
- 程序启动时加载数据；
- 对读取的数据进行基本格式和合法性检查。

## 4. 数据结构与算法

项目根据不同数据的访问特点选择数据结构，而不是为了数量而强行使用。

### 哈希表

用于建立：

```text
用户编号 → 用户对象
设备编号 → 设备对象
```

支持关键对象的快速精确查询。

### 树

主要用于组织设备分类等具有层次关系的数据。

具体树结构的实现形式根据详细设计确定。

### 链表

用于维护适合动态增长的记录，例如设备借用历史。

### 队列

用于维护普通等待任务，遵循先进先出的处理规则。

### 优先队列

用于需要根据明确客观规则进行优先处理的调度任务。

### 栈

用于保存可撤销的操作记录，实现撤销功能。

### 主要算法

项目计划实现和使用：

- 查找；
- 排序；
- 树遍历；
- 时间区间冲突检测；
- 队列调度；
- 数据插入、删除与更新；
- 必要的复杂度分析。

核心数据结构尽量自行实现，以体现课程要求；Qt、文件操作以及其他与课程核心无关的功能使用成熟库完成。

## 5. 系统结构

项目采用较为简单的分层设计，避免过度复杂的工程结构。

```text
┌───────────────────────────────┐
│           Qt GUI              │
│ 输入 / 显示 / 用户交互         │
└───────────────┬───────────────┘
                ↓
┌───────────────────────────────┐
│        业务逻辑层              │
│ 用户 / 设备 / 预约 / 调度       │
└───────────────┬───────────────┘
                ↓
┌───────────────────────────────┐
│      数据结构与算法层          │
│ 哈希表 / 树 / 链表 / 队列 / 栈  │
└───────────────┬───────────────┘
                ↓
┌───────────────────────────────┐
│         数据持久化              │
│         本地文件                │
└───────────────────────────────┘
```

GUI 层主要负责输入和显示，不将大量核心算法直接写入 `MainWindow`。

## 8. 开发原则

### 简单优先

优先使用容易理解、调试和维护的设计，不进行不必要的过度抽象。

### 数据结构服务于业务

每一种数据结构都应能够说明：

```text
数据是什么
↓
数据有什么特点
↓
为什么采用这种结构
↓
需要进行什么操作
↓
复杂度如何
```

### GUI 与核心逻辑分离

GUI 主要负责：

```text
输入
↓
调用业务逻辑
↓
显示结果
```

核心数据结构和算法尽量保持独立。

### 注释简洁

只为必要的算法、特殊逻辑和边界条件添加注释，不写长篇解释。

### 重视数据正确性

重点检查：

- 空输入；
- 重复编号；
- 非法时间；
- 时间冲突；
- 非法状态转换；
- 不存在的用户或设备；
- 重复借用、归还；
- 文件数据异常。

## 10. Git 版本管理

项目使用 Git 进行版本管理。

每完成一个相对独立且能够正常运行的功能后进行一次提交，例如：

```text
feat: add device management
feat: add reservation conflict detection
feat: add waiting queue
feat: add borrow history
feat: add reservation ui
fix: handle invalid reservation time
refactor: simplify device manager
```

避免出现只有一个：

```text
final project
```

的提交历史。

不提交：

```text
build/
*.user
Qt Creator 临时文件
IDE 缓存
其他生成文件
```
