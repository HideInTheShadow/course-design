# 实验室共享设备预约与冲突调度系统

## 1. 项目简介

本项目是计算机科学与工程实践课程设计，采用 **C++ + Qt** 开发，面向高校实验室共享设备的预约与管理场景。

系统主要解决实验室共享设备在使用过程中产生的设备查询、预约管理、时间冲突、设备借用与归还、等待任务以及历史记录管理等问题。

项目重点不是简单的信息增删改查，而是研究不同类型数据在内存中的组织方式，并利用数据结构与算法完成高效的数据管理和业务操作。

------

## 2. 项目目标

系统需要实现一个具有完整 GUI 的本地实验室共享设备管理程序，主要目标包括：

- 快速查询和管理用户、设备信息；
- 支持设备预约与取消；
- 自动检测预约时间冲突；
- 管理设备借用、归还及设备状态；
- 维护设备不可用时的等待任务；
- 查询设备借用历史；
- 支持必要的操作撤销；
- 实现本地数据保存与加载；
- 对非法输入和异常操作进行检查；
- 通过 Qt GUI 直观展示设备及预约状态。

------

## 3. 核心功能

### 用户管理

- 用户信息添加、修改、删除；
- 用户信息查询；
- 用户编号唯一性检查。

### 设备管理

- 设备添加、修改、删除；
- 多级设备分类，按分类浏览设备；
- 设备状态显示与更新；
- 设备列表可按任意列排序查看。

### 预约管理

- 创建预约；
- 取消预约；
- 查询预约；
- 预约时间冲突检测；
- 预约状态维护。

系统将预约时间统一表示为半开区间：

```text
[start, end)
```

两个预约区间存在冲突的条件为：

```text
start1 < end2 && start2 < end1
```

### 借用与归还

- 设备借用；
- 设备归还；
- 设备状态更新；
- 借用历史记录。

### 等待与调度

当设备在目标时段已被预约时：

- 用户可以选择排队等待，等待任务进入等待队列；
- 队列按「先到先服务」处理，保证公平，不引入主观的优先级评分；
- 设备时段释放（取消预约或归还设备）后，按排队顺序重新检查，不再冲突的任务转为有效预约；
- 设备状态随调度结果更新。

### 操作撤销

保存管理员的重要操作记录，并支持撤销最近一次可撤销操作。

### 数据持久化

- 程序退出前保存数据；
- 程序启动时加载数据；
- 对读取的数据进行基本格式和合法性检查。

## 4. 数据结构与算法

项目根据不同数据的访问特点选择数据结构，而不是为了数量而强行使用。

### 哈希表（链地址法，自行实现）

用于建立：

```text
用户编号 → 用户对象
设备编号 → 设备对象
预约编号 → 预约对象
```

支持关键对象的快速精确查询。实现为「桶数组 + 单链表」，字符串键使用 BKDR 哈希。

平均时间复杂度 O(1)，最坏 O(n)（所有键都落进同一个桶时）。

### 树（孩子兄弟表示法，自行实现）

用于组织多级设备分类：

```text
电子测量
├── 示波器类
└── 信号源类
```

每个节点只保存「第一个孩子」和「下一个兄弟」两个下标，就能表示任意多个孩子，不必为每个节点维护不定长的孩子数组。节点集中存放在动态数组中，父子关系用下标表示，扩容时不会产生悬空指针。

设备只保存分类名，分类树由设备管理器单独维护，删除分类不会牵连设备对象本身。

### 链表（自行实现）

用于维护设备借用历史：记录只追加、按先后顺序遍历，因此使用带头结点、带尾指针的单向链表，尾部追加 O(1)。

### 队列（链式实现，自行实现）

用于维护普通等待任务，遵循先进先出：

```text
预约冲突 → 进入等待队列 → 设备时段释放 → 队首不再冲突的任务转为有效预约
```

等待队列只保存预约编号，预约实体统一存放在哈希表中，避免同一份数据两处保存。

### 栈（自行实现）

用于保存可撤销的操作记录（目前为「取消预约」）：

```text
取消预约 → 记录入栈 → 撤销时弹出 → 按取消前的状态恢复
```

### 优先队列

当前**未引入**。等待任务按「先到先服务」处理，业务上不存在客观、可解释的优先级规则；没有实际依据的主观评分体系不予设计。若后续出现真实的优先调度需求（例如维修中的设备优先恢复），再按相同风格补充实现。

### 主要算法

| 算法 | 说明 | 复杂度 |
|---|---|---|
| 时间区间冲突检测 | 半开区间 `[start, end)`，同设备上逐个比较 | O(n) |
| 等待任务调度 | 设备时段释放后按队列顺序重试，可提升的转为有效预约 | O(m)，m 为队列长度 |
| 编号查询 | 哈希表按键查找 | 平均 O(1) |
| 分类树遍历 | 前序遍历，输出「分类名 + 节点下标 + 父下标」 | O(n) |
| 分类删除 | 删除节点及其子树，数组重建并重新编号 | O(n) |
| 借用历史追加 | 链表尾插 | O(1) |
| 撤销 | 栈弹出一条操作记录并按原状态恢复 | O(1)（恢复本身需做冲突检测，O(n)） |

核心数据结构均为自行实现；Qt、文件读写等与课程核心无关的部分使用标准库和 Qt 完成。

## 5. 系统结构

项目采用较为简单的分层设计，避免过度复杂的工程结构。

```text
┌──────────────────────────────────────────┐
│                 Qt GUI                   │
│  设备与预约 / 预约与等待 / 借用历史 / 管理  │
│  输入、显示、调用业务方法、提示操作结果      │
└───────────────────┬──────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│              service（业务逻辑）           │
│  LabService 协调流程：预约 → 冲突 → 等待    │
│  → 借用 → 归还 → 调度 → 撤销               │
│  UserManager / DeviceManager /            │
│  ReservationManager 负责各自对象的规则      │
└─────────┬──────────────────────┬─────────┘
          ↓                      ↓
┌────────────────────┐  ┌────────────────────────┐
│   model（实体）     │  │  datastruct（自实现容器）│
│  User / Device     │  │  HashTable / Tree       │
│  Reservation       │  │  LinkedList / Queue     │
│  BorrowRecord      │  │  Stack                  │
└────────────────────┘  └────────────────────────┘
                    ↑
┌───────────────────┴──────────────────────┐
│          storage（数据持久化）             │
│         启动载入 / 退出保存，本地文本文件   │
└──────────────────────────────────────────┘
```

依赖是单向的：`gui → service → model + datastruct`，`storage` 只调用 `service` 的公开接口。`model`、`datastruct`、`service`、`storage` 均不包含任何 Qt 头文件，因此可以脱离 GUI 单独编译和测试；Qt 只出现在 `gui` 这一层。

GUI 层只负责输入和显示，核心算法与数据结构不写入 `MainWindow`。

## 6. 核心数据模型

核心实体：

```text
User          用户编号、姓名、部门
Device        设备编号、名称、分类、状态、存放位置
Reservation   预约编号、用户编号、设备编号、开始时间、结束时间、状态
BorrowRecord  记录编号、设备编号、用户编号、借用时间、归还时间、状态
```

管理类：

```text
UserManager         持有 HashTable<int, User>
DeviceManager       持有 HashTable<int, Device> + Tree<string>（分类树）
ReservationManager  持有 HashTable<int, Reservation> + Queue<int>（等待队列）
LabService          持有上述三个管理器 + LinkedList<BorrowRecord> + Stack<UndoAction>
```

`LabService` 是业务协调者：单个对象自身的规则由各管理器负责，跨越多个对象的约束（例如「还有有效预约的设备不能删除」）集中在 `LabService` 中。

核心对象都做了封装：成员变量全部私有，外部通过成员函数读写，编号由管理器内部自增分配，保证唯一且不复用。

设备状态与预约状态：

```text
设备：空闲 / 已预约 / 已借出 / 维修中
预约：有效 / 已取消 / 等待中
```

设备状态由预约与借用记录推导：有有效预约即「已预约」，借出期间为「已借出」，其余为「空闲」；「维修中」只能由管理员手动设置。归还或取消预约后按剩余的有效预约重新计算。

## 8. 开发原则

### 简单优先

优先使用容易理解、调试和维护的设计，不进行不必要的过度抽象。

### 数据结构服务于业务

每一种数据结构都应能够说明：

```text
数据是什么
↓
数据有什么特点
↓
为什么采用这种结构
↓
需要进行什么操作
↓
复杂度如何
```

### GUI 与核心逻辑分离

GUI 主要负责：

```text
输入
↓
调用业务逻辑
↓
显示结果
```

核心数据结构和算法尽量保持独立。

### 注释简洁

只为必要的算法、特殊逻辑和边界条件添加注释，不写长篇解释。

### 重视数据正确性

重点检查：

- 空输入；
- 重复编号；
- 非法时间；
- 时间冲突；
- 非法状态转换；
- 不存在的用户或设备；
- 重复借用、归还；
- 文件数据异常。

## 9. 编译与运行

项目使用 CMake 管理构建，并使用 Qt 提供 GUI 功能。

本项目实际使用的开发环境：

```text
Qt        6.11.2（MinGW 64 位）
编译器     Qt 自带的 MinGW 13.1.0（D:\Qt\Tools\mingw1310_64）
CMake      3.30.5
Ninja      1.12.1
C++ 标准   C++17
```

注意：编译器必须使用 Qt 自带的 MinGW，不要使用 PATH 中其它来源的 MinGW。两者虽然
GCC 版本可能相同，但线程模型（posix / win32）不同，libstdc++ ABI 不兼容，混用会链接报错。

配置与构建：

```bash
cmake -S . -B build -G Ninja \
  -DCMAKE_CXX_COMPILER=D:/Qt/Tools/mingw1310_64/bin/g++.exe \
  -DCMAKE_PREFIX_PATH=D:/Qt/6.11.2/mingw_64
cmake --build build
```

运行 GUI（命令行方式需要把 Qt 的 bin 目录加入 PATH；Qt Creator 会自动处理）：

```bash
export PATH="/d/Qt/6.11.2/mingw_64/bin:/d/Qt/Tools/mingw1310_64/bin:$PATH"
./build/labapp.exe
```

运行测试（不依赖 Qt，可直接执行）：

```bash
./build/test_model.exe
./build/test_datastruct.exe
./build/test_service.exe
./build/test_lab_service.exe
./build/test_storage.exe
```

测试使用 `assert` 检查结果，因此必须使用 Debug 构建（Release 下 `NDEBUG` 会禁用检查）。

### 数据文件

程序启动时从**当前工作目录**下的 `lab_data.txt` 读取数据，退出前写回。文件不存在时按空数据启动。

文件采用「分节 + 竖线分隔」的文本格式，可以直接打开查看：

```text
[用户]      编号|姓名|部门
[分类]      节点下标|父节点下标|分类名
[设备]      编号|名称|分类|状态|存放位置
[预约]      编号|用户编号|设备编号|开始时间|结束时间|状态
[等待队列]  预约编号（按排队先后各占一行，顺序即先后次序）
[借用记录]  编号|设备编号|用户编号|借用时间|归还时间|状态
```

时间统一使用分钟粒度的整数，例如 `600` 表示 10:00，区间为 `[start, end)`。

载入时会检查每条记录的字段个数、数值范围、编号重复情况以及引用的用户/设备是否存在，
格式不正确的记录被跳过（不会进入核心数据结构），跳过条数在启动时通过控制台提示。

设备分类按下标顺序保存：父节点下标一定小于子节点，因此载入时一次遍历即可重建整棵分类树。
